## 三、标准工作流程

### 3.1 前置条件

在提交问题前，请尽量准备以下材料（按优先级排序）：

1. **完整错误信息**：`.log` 文件末尾 20-30 行，或 Overleaf 红色报错框中的原文。注意：不要只复制"! LaTeX Error: ..."这一行，需要包含其后的上下文行。
2. **最小工作示例（MWE）**：能复现问题的最简 `.tex` 文件。删除所有无关章节，保留触发问题的核心代码。如果问题涉及宏包冲突，请保留全部宏包引用。
3. **环境描述**：编译器类型（pdfLaTeX / XeLaTeX / LuaLaTeX）、宏包版本（可在导言区添加 `\listfiles` 后查看 `.log` 开头的列表）、操作系统。
4. **期望行为**：明确描述你希望的结果，例如"编译通过"、"图 3 出现在第 2 节末尾"、"参考文献格式符合 GB/T 7714"。

### 3.2 执行步骤

**步骤 1：问题分类**  
根据你提供的信息，我会先判断问题属于哪一类别：编译错误、模板适配、结构解析、还是排版优化。分类决定后续处理路径。

**步骤 2：错误定位（针对编译错误）**  
- 提取 `.log` 中的关键错误行（以 `!` 开头）。
- 回溯错误发生前的最近 5-10 行，查找上下文。
- 检查是否有宏包冲突警告（`LaTeX Warning: ...`）。
- 输出错误码（见第五节）和定位结果。

**步骤 3：方案生成**  
根据问题类型输出解决方案：
- 编译错误 → 给出修正后的代码片段 + 修改说明。
- 模板适配 → 输出「模板要求 → 当前状态 → 差距清单」对照表 + 具体修改命令。
- 结构解析 → 输出 Markdown 大纲 + 浮动体统计表 + 交叉引用检查结果。

**步骤 4：验证建议**  
提供验证方法，例如：重新编译后应观察到的现象、需要检查的 `.log` 关键行、或 Overleaf 中应消失的报错图标。

### 3.3 输出规范

所有输出遵循以下格式：

- **代码片段**：使用 Markdown 代码块，标注语言（如 `latex`）。修改处用注释 `% CHANGED:` 标注。
- **对照表**：使用 Markdown 表格，左列为项目，右列为状态/说明。
- **错误码**：格式为 `[LATEX-XXX]`，后跟简短描述。

## 五、错误码体系

以下错误码覆盖常见 LaTeX 编译问题。遇到报错时，可对照此表快速定位。

| 错误码 | 错误类型 | 典型提示话术 | 修正步骤 |
| :--- | :--- | :--- | :--- |
| `[LATEX-101]` | 未定义控制序列 | `! Undefined control sequence.` | 1. 检查命令拼写；2. 确认所需宏包已加载；3. 检查命令是否在正确环境中使用 |
| `[LATEX-102]` | 文件未找到 | `! File 'xxx.sty' not found.` | 1. 确认宏包已安装；2. 检查文件名大小写；3. 使用 `\usepackage` 时确认拼写 |
| `[LATEX-103]` | 环境不匹配 | `! LaTeX Error: \begin{xxx} on input line N ended by \end{yyy}` | 1. 检查 `\begin`/`\end` 配对；2. 确认环境嵌套正确 |
| `[LATEX-104]` | 浮动体过多 | `! LaTeX Error: Too many unprocessed floats.` | 1. 增加浮动体位置参数（如 `[htbp]`）；2. 使用 `\clearpage` 强制输出；3. 减少浮动体数量 |
| `[LATEX-105]` | 引用未定义 | `LaTeX Warning: Reference 'xxx' on page N undefined` | 1. 检查 `\label` 是否存在；2. 确认编译两次；3. 检查 `\ref` 拼写 |
| `[LATEX-106]` | 宏包选项冲突 | `! LaTeX Error: Option clash for package xxx` | 1. 检查宏包加载时的选项；2. 使用 `\PassOptionsToPackage` 统一选项 |
| `[LATEX-107]` | 字体错误 | `! Font xxx not found.` | 1. 确认字体已安装；2. 检查字体命令拼写；3. 考虑使用 XeLaTeX/LuaLaTeX 加载系统字体 |
| `[LATEX-108]` | 数学公式错误 | `! Missing $ inserted.` | 1. 检查数学环境是否闭合；2. 确认特殊字符已转义 |

## 六、常见坑与反模式

以下列出使用本 Skill 时最常见的 5 个误区，以及对应的正确做法。

### 反模式 1：只给单行错误信息
- **错误做法**：只提供 `! Undefined control sequence.` 这一行。
- **正确做法**：提供 `.log` 末尾 20-30 行，或 Overleaf 报错框的完整内容。
- **原因**：单行错误无法定位上下文，容易误判。

### 反模式 2：提供完整项目而非 MWE
- **错误做法**：将整个项目打包粘贴（或描述整个项目结构）。
- **正确做法**：精简到最小工作示例，删除无关章节。
- **原因**：MWE 能快速隔离问题，避免其他代码干扰判断。

### 反模式 3：忽略编译器类型
- **错误做法**：不说明使用 pdfLaTeX 还是 XeLaTeX。
- **正确做法**：明确编译器类型，必要时提供 `\listfiles` 输出。
- **原因**：不同编译器对字体、宏包支持不同，解决方案可能完全不同。

### 反模式 4：期望一次编译解决所有问题
- **错误做法**：修改后只编译一次，发现引用未更新就认为修改无效。
- **正确做法**：涉及交叉引用、目录、参考文献时，连续编译两次（或按需三次）。
- **原因**：LaTeX 的引用机制需要多轮编译才能稳定。

### 反模式 5：直接要求"帮我改好"
- **错误做法**：不提供期望行为，只说"帮我改好"。
- **正确做法**：明确说明期望结果，如"编译通过"、"图表在正确位置"、"符合某期刊格式"。
- **原因**：没有期望行为，输出方案可能偏离你的真实需求。
